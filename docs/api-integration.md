# Implementation interfaces

Current source locations follow `docs/project-structure.md`: database/transactions in `backend/src/config/database.ts`, auth in `backend/src/middleware/auth.middleware.ts`, HTTP helpers in `backend/src/utils/http.ts`, AppError in `backend/src/errors/app-error.ts`, and HTTP registrations/handlers in `backend/src/routes` / `backend/src/controllers`. Older short filenames below describe the same interfaces before the directory reorganization.

All routes `/api/v1`, JSON success `{data,meta?}`. Error `{error:{code,message,fields?,requestId}}`. Dates ISO, IDs UUID, version integer. Admin cookie and `X-CSRF-Token` on writes, token from GET `/admin/auth/me`. Login Origin must match APP_ORIGIN.

Shared `packages/contracts/src/index.ts` defines Content, guestSchema (camelCase), rsvpSchema, wishSchema, assetIds, publicationErrors and staticMedia. Locations use UTC startAt/endAt, venueName, address, googleMapsUrl, mapImageAssetId and entranceNote. Theme palettes are cream, sage, rose and blue. Fonts are serif, sans, lora and be-vietnam-pro. When enabled, the gallery displays the 30 bundled photos `01.webp` through `30.webp` in numeric order from `/invitation-assets/photos/companions/`. The contract accepts legacy gallery items for revision compatibility. The renderer uses the bundled sequence.

Guest `/guest/invitation` returns `{content,media,guest:{displayName,fullName,salutation},personalMessage,rsvp,wish,canRsvp,canCreateOrEditWish,canWithdrawWish,eventId}`. The `media` object maps each referenced catalog UUID to `{id,url,alt,type,width?,height?,srcSet?}`. Admin previews use the same static URLs. RSVP and wish records are nullable. An existing wish includes deletedAt and version. Body expectedVersion is 0 when the record is absent. All guest routes use `Authorization: Bearer <token>`. Opened is POST. RSVP and wish PUT requests require a UUID `Idempotency-Key` header. Wish visibility PATCH accepts consentPublic false and expectedVersion. Wish DELETE takes expectedVersion in the body. Wall GET returns `{items,nextCursor}` with public fields. Fetch the calendar with Authorization and read it as a blob.

Admin current event GET `/admin/events/current`: `{id,version,draftRevisionId,publishedRevisionId,publishedAt,rsvpEnabled,wishesEnabled,wallEnabled,draft:{contentJson,...},published:{contentJson,...}|null}`. Draft PATCH `/admin/events/:id/draft`: body `{content:Content}`, If-Match header Event version; response same event DTO. Publish/unpublish POST `{expectedVersion}`; controls PATCH expectedVersion and booleans. Preview GET returns InvitationView plus preview true, guestId query optional. Dashboard `{total,attending,declined,unanswered,pendingWishes,opened}`.

Admin guests GET `/admin/events/:id/guests`: query q,group,status (ATTENDING/DECLINED/UNANSWERED),archived (true/false/all),page,pageSize,sort; data `{items,total,page,pageSize}`. Each guest safe admin record plus invitation `{id,version,revokedAt,openedAt,rsvp,wish}` (no hash/ciphertext). POST guestSchema camelCase response guest+invitation. PATCH `/admin/guests/:id`: guestSchema + expectedVersion + expectedInvitationVersion; body includes all current form fields. Archive/restore POST `{expectedVersion}`. Link GET `/admin/invitations/:id/link`: `{url,message}`. Revoke/rotate POST `{expectedVersion}`. Admin RSVP PUT `{status,note,expectedVersion,reason}`.

Admin wishes GET `/admin/events/:id/wishes`: query status optional NONE/PENDING/APPROVED/HIDDEN/DELETED, page/pageSize; `{items,total,page,pageSize}` records include invitation.guest. Moderation PATCH `/admin/wishes/:id/moderation`: `{action:'APPROVE'|'HIDE',expectedVersion}`. Pin PATCH `{isPinned,expectedVersion}`.

Imports export `importRouter`. Routers receive mount API root, use `requireAdmin` on admin endpoints. Helpers in http.ts: `AppError(status,code,message,fields?)`, `ok(res,data,status=200)`, `ownedEvent(req,eventId,tx?)` returns owned event or throws; `audit(tx,req,action,eventId,entityType,entityId,metadata?)`; `pagination(req)` -> `{page,pageSize,skip}`. auth.ts exports requireAdmin and requireGuest. Request `req.admin={id,email,csrfToken,sessionId}`, `req.invitation` Prisma include guest,event,rsvp,wish; `req.requestId`. `config` camelCase properties, `prisma` global. crypto.ts createInvitationToken(id) returns token,tokenHash,tokenCiphertext,keyVersion; decryptInvitationToken(id,ciphertext,keyVersion); hashToken(string).

Imports endpoints: GET `/admin/imports/template` xlsx; POST `/admin/events/:id/imports/inspect` multipart file -> `{sheets:[{name,headers:string[]}]}`; POST preview multipart file,sheet,mapping(JSON canonical snake_case => original header). GET batch -> batch DTO `{id,status,summary,rows,errors,expiresAt}`. POST commit `{}` Idempotency-Key required -> `{created,updated,unchanged}`. GET batch/report returns xlsx of errors. Exports GET `/admin/events/:id/exports/:kind`, kind links/responses, filters as guests incl history. Dates/filter metadata in file.

To prepare an XLSX upload, POST `{purpose:"IMPORT",name,bytes}` to `/admin/events/:id/uploads`. Direct upload mode returns a private PUT URL, headers and uploadId. After the PUT, send uploadId in the JSON inspect and preview requests. Local mode uses the multipart requests above. XLSX uploads are limited to 5 MiB.

The editor selects images and audio from `staticMedia`. Draft and publication validation check catalog UUIDs. Publication also checks the asset types for image and music fields.

Database Prisma schema is in backend/prisma/schema.prisma. Guest.module and imports create Invitation ID first, encrypt token with ID AAD; `prisma.invitation.create` data omits plaintext token. Import rows store versions, invitation fields separately. Transactions use serializable or row lock plus conditional versions and retry serialization failures. `withTransaction(fn)` in db.ts retries P2034 up to 3, and `idempotent(req,scope,actorHash,body,fn)` in http.ts authenticates before entry and transactionally runs fn(tx), records/replays data, requires header, hashes canonical request body. Guest route handlers recheck activity/publication within same transaction.

Tests: Vitest fileParallelism false; `backend/tests/helpers.ts` exports setupTestData() returning admin,event,content,guest,invitation,token,csrf,cookie; resetTestDatabase() deletes children then parents. Integration uses TEST_DATABASE_URL if set, otherwise DATABASE_URL only when database name ends `_test`. Root prepares tests database invitations_test and `.env.test`; never reset dev DB. Tests requests set Origin http://localhost:5173.
